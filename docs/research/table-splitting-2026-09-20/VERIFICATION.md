# Проверка и воспроизведение исследования

Дата: 20 сентября 2026. [Основной отчёт](../../table-splitting-research-2026-09-20.md).

## Что проверено

- JSON-артефакты читаются; каждая основная и дополнительная кодовая запись
  содержит свидетельства.
- Все 130 Git HEAD сверены с manifest; два Go-архива проверяются как архивные
  версии по metadata proxy, без вымышленного локального Git HEAD.
- 134 ссылки в `code-findings.json` и `additional-code-findings.json` проверены
  по локальным файлам: путь, номер строки, дословное наличие сохранённого
  фрагмента и соответствие commit в URL.
- 166 ссылок на код из Markdown проверены по тому же manifest и локальным файлам.
  Это проверка содержимого checkout, не обещание постоянной доступности GitHub.
- Относительные ссылки между материалами проверены на существование файлов.
- Реестр сверяет все 279 продуктовых строк исходного каталога, отдельно
  учитывает Yandex Data Transfer внутри строки и девять прежних названий.
  Полнота учёта не равна доказательству всех возможностей каждого продукта.
- Независимый read-only review уточнил snapshot restart, fencing на стороне
  sink, конечный горизонт backfill, partial CDC images, NULL и условия
  SeaTunnel/Daft/Beam/Flink. Замечания включены в итоговый текст.

`just test-affected-dry` сообщил: `No executable code is affected.`
Итоговый `just check-affected` завершился с кодом **0** примерно за **0,05 с**,
также сообщил `No executable code is affected.` Компиляция не требовалась и
не запускалась. Это не результат release gate.

Новые benchmarks, competitor binaries, production tests, Rust builds, Clippy,
Docker/E2E и формальная модель DBLog **не запускались**. Коммерческие выводы
относятся к приведённой редакции/документации. Ссылки на документацию актуальны
на дату просмотра, но сайты могут измениться. Это не независимая проверка
закрытого engine.

## Локальные исходники

Локальный корень относительно репозитория Transferia:
`target/research/table-splitting/sources/`. На момент проверки — около **1,4 ГБ**,
130 Git checkout и два архива. Этот каталог исключён из Git существующим
правилом `/target/`; отчёт и manifest можно коммитить без vendoring чужих проектов.

[SOURCE-MANIFEST.json](SOURCE-MANIFEST.json) — источник истины для полученных
версий. `repositories.json` — исходный список загрузки, не замена manifest;
дополнительная зависимость Feldera/ETL и восстановленные архивы отражены в
manifest. Там же указаны реально существующие и отсутствующие sparse paths.
Например, скачивание Dremio не означает наличия в нём закрытых JDBC plugins.

Для повторного получения Git-компонента:

1. Взять `remote_url`, `commit` и `actual_sparse_paths` из manifest.
2. Создать новый пустой каталог. Получить репозиторий с `--filter=blob:none`,
   `--depth 1`, `--sparse`, затем отдельно fetch зафиксированного commit, если
   текущий HEAD отличается.
3. Установить указанные sparse paths; для полного checkout отключить sparse.
4. Сделать detached checkout зафиксированного commit и сравнить `git rev-parse HEAD`.
   Не заменять недоступную ревизию молча текущей веткой.
5. Для свидетельства открыть `path` на `line` из JSON findings. Названия файлов
   и строки относятся именно к этому commit.

Для `downloaded-module-archive` использовать `download_url` и `version`.
Поля `archive_origin` содержат VCS hash из Go proxy. Архивные версии pg_flo
v0.0.15 и Bindplane v1.35.0 не доказывают возможности нынешних поставок.
Исторические GitHub permalinks этих проектов могут не открываться; рабочее
свидетельство — локально сохранённый архив и ссылка Go proxy.

## Неустранимые в этом исследовании пробелы

| Объект | Что сделано | Чего нет |
|---|---|---|
| Artie `artie-labs/transfer` | Попытка Git и проверка альтернативной доступности; коммерческая техническая статья включена | Репозиторий возвращает Not Found; локальной копии engine нет |
| Talend `Talend/tdi-studio-se` | Попытка загрузки исторического OSS; документация tJDBCInput рассмотрена отдельно | Репозиторий возвращает Not Found; исходники именно Open Studio не получены |
| Закрытые продукты без описанного boundary algorithm | Проверенные документы и границы подтверждения перечислены в COMMERCIAL | Нельзя восстановить непубличный алгоритм или доказать отсутствие функции |
| Полная корректность реализаций | Аудит конкретных source paths, аналитические риски | Нет runtime repro каждого edge case и нет сертификации всех connectors |

Никакие недоступные исходники не подменены похожим проектом или deployment
charts. Точная оценка производительности предложенных алгоритмов остаётся
будущим экспериментом, программа которого приведена в основном отчёте.
